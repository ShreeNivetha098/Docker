Pipeline stages

These are the stages in the Jenkinsfile. Jenkins runs them in this order.

  1. 1

    Checkout

    Retrieve the source code from GitHub.

  2. 2

    Install Dependencies

    Install the Node.js packages the application needs.

  3. 3

    Test

    Run automated tests. A failure stops the pipeline.

  4. 4

    Build

    Build a Docker image from the verified source.

  5. 5

    Deploy

    Stop the previous container and start the new image.

  6. 6

    Verify

    Request /health and require a successful response.

CI

Continuous Integration

Continuous Integration means new code is regularly combined with the shared project and checked automatically. In this demo, Jenkins checks out the GitHub repository, installs dependencies, and runs the test suite. If a test fails, the pipeline stops before a new image is deployed.

  • Checkout pulls the committed application files.
  • Install Dependencies runs npm ci.
  • Test runs npm test and fails the job on an error.

CD

Continuous Deployment

Continuous Deployment means a build that passes its checks is released as the running version. Here, Jenkins builds a Docker image and replaces the container that serves this page on localhost. Opening or refreshing the browser shows the version that just deployed.

  • Build creates the image with Docker.
  • Deploy removes the previous container, then starts the new one.
  • Verify confirms the new container answers on port 3000.

Tools in this pipeline

Each tool has one job. None of them is a paid or cloud service.

GitHub

Source history

Git records each change. GitHub stores the repository so Jenkins can check out the same commit you pushed from your computer.

Jenkins

Pipeline runner

Jenkins runs the Jenkinsfile stages. For this project you start a run with Build Now, unless you later enable polling.

Docker

Packaged runtime

Docker builds an image that contains Node.js and this application, then runs it in a container mapped to localhost port 3000.

What is automated

Pushing code does not, by itself, start Jenkins. You trigger the job manually with Build Now. After the job starts, checkout, install, test, image build, container replacement, and the health check run without further clicks. You then refresh this page to see the result.
